CsAC 项目安全问题列表
生成日期: 2026-05-31
========================================

一、严重安全问题（必须修复）
----------------------------------------

3. 密码哈希使用 SHA-256，无盐值
   文件: rpc/core.php 第415行
   代码:
     function hash_password($pwd, $username): string
     {
         return hash('sha256', (string)$pwd . (string)$username);
     }
   问题: SHA-256 是快速哈希算法，不适合密码存储。用用户名做"盐"也不安全（用户名可预测），且同一用户名+密码组合总是产生相同哈希，容易被彩虹表攻击。
   建议: 使用 password_hash() (bcrypt/Argon2) 替代。

5. 升级密码接口不强制校验旧密码
   文件: rpc/core.php 第1388-1394行
   代码:
     function csac_api_user_upgrade_password(): void
     {
         // ...
         csac_change_password($uid, $user, false); // requireOld = false
     }
   问题: upgrade_password 接口不验证旧密码，如果用户 Session 被劫持，攻击者可以直接修改密码。
   建议: 至少要求验证旧密码，或要求二次身份验证。

6. CORS 默认回退暴露了生产域名
   文件: rpc/core.php 第83-88行
   代码:
     if ($origin !== '' && in_array($origin, $allowed, true)) {
         header('Access-Control-Allow-Origin: ' . $origin);
     } else {
         header('Access-Control-Allow-Origin: https://cschat.ccccocccc.cc');
     }
   问题: 当请求来源不在白名单时，默认回退到 cschat.ccccocccc.cc，而非拒绝。这意味着任何来源的请求都能以该域名身份执行跨域请求。
   建议: 不在白名单时不应设置 Allow-Origin，直接拒绝跨域请求。

7. 调试模式绕过所有权限检查
   文件: rpc/core.php 第470-476行
   代码:
     function requireLogin(): int
     {
         if (csac_is_debug_mode()) {
             $uid = csac_debug_uid();
             csac_touch_user($uid);
             return $uid;
         }
         // ...
     }
   问题: 调试模式激活后，requireLogin() 不验证真实登录状态，requireGroupMember()、requireGroupOwner()、requireRoomNotBanned() 等所有权限检查都被绕过。结合问题 #2，这是一个极高风险。
   建议: 生产环境应完全禁用调试模式，或至少需要额外身份验证。


二、高风险问题
----------------------------------------

8. JSONP 回调存在 XSS 风险
   文件: rpc/core.php 第119-127行
   代码:
     if (isset($_GET['callback']) && is_string($_GET['callback']) && $_GET['callback'] !== '') {
         $callback = preg_replace('/[^A-Za-z0-9_.$]/', '', $_GET['callback']);
         // ...
         echo $callback . '(' . json_encode($data, ...) . ');';
     }
   问题: 虽然对 callback 做了字符过滤，但允许 $ 和 . 字符，在某些浏览器上下文中仍可能被利用进行 XSS 攻击。JSONP 本身就是一种不安全的跨域方式。
   建议: 移除 JSONP 支持，改用 CORS 进行跨域。

9. test 路由暴露在生产环境
   文件: rpc/core.php 第261行
   代码:
     'test' => 'csac_api_test',
   问题: 测试接口 csac_api_test() 不需要登录即可调用，会执行数据库查询，可能被用于探测数据库状态。
   建议: 生产环境移除测试路由。

10. debug/activate、debug/deactivate、debug/status 路由暴露
    文件: rpc/core.php 第263-265行
    代码:
      'debug/activate' => 'csac_api_debug_activate',
      'debug/deactivate' => 'csac_api_debug_deactivate',
      'debug/status' => 'csac_api_debug_status',
    问题: 调试接口公开暴露在路由中，debug/status 不需要认证即可查看调试模式状态。
    建议: 生产环境应移除或通过配置禁用这些路由。

11. 上传目录权限过宽
    文件: rpc/core.php 第848行
    代码:
      if (!is_dir($absoluteDir) && !mkdir($absoluteDir, 0775, true) && !is_dir($absoluteDir)) {
    问题: 目录权限 0775 意味着组用户有完全读写执行权限，在某些共享主机环境中可能不安全。
    建议: 使用 0755 或更严格的权限。

12. 文件上传缺少文件内容验证
    文件: rpc/core.php 第838-870行
    问题: 虽然验证了 MIME 类型，但没有验证文件的实际内容（如图片的 magic bytes）。攻击者可以伪造 MIME 类型上传恶意文件。
    建议: 对图片文件使用 getimagesize() 验证是否为合法图片。

13. 上传文件扩展名可被客户端控制
    文件: rpc/core.php 第870-873行
    代码:
      $ext = $mimeToExt[$mime] ?? strtolower(pathinfo((string)($file['name'] ?? ''), PATHINFO_EXTENSION));
    问题: 当 MIME 检测失败时，回退到客户端提供的文件名扩展名，攻击者可上传 .php 等危险扩展名文件。
    建议: 严格限制允许的扩展名白名单，不信任客户端文件名。


三、中等风险问题
----------------------------------------

14. error_log 写入 Web 可访问目录
    文件: rpc/core.php 第109行
    代码:
      @error_log($line, 3, __DIR__ . '/rpc_error.log');
    问题: 错误日志写入 rpc/ 目录下，可能通过 HTTP 直接访问，泄露服务器内部信息（文件路径、错误详情）。
    建议: 将日志写入 Web 根目录之外，或通过 .htaccess 禁止访问 .log 文件。

15. 缺少 CSRF 防护
    问题: 所有 POST 请求仅依赖 Session Cookie 进行认证，没有 CSRF Token 验证。攻击者可以构造恶意页面诱导已登录用户执行操作。
    建议: 实现 CSRF Token 机制，或使用 SameSite=Strict Cookie 属性。

16. Session 固定攻击风险
    文件: rpc/core.php 第1105行
    问题: 登录时虽然调用了 session_regenerate_id(true)，但注册时是在 csac_commit() 之后才调用，如果注册过程中 Session 已被攻击者预设，存在风险。
    建议: 在注册流程开始时就调用 session_regenerate_id(true)。

17. 注销账号不验证身份
    文件: rpc/core.php 第1396-1420行
    问题: 注销账号是破坏性操作，但不需要密码确认。如果用户 Session 被劫持，账号将被永久删除。
    建议: 要求输入密码确认后才能注销。

18. 群组踢人后重置邀请码
    文件: rpc/core.php 第2622行
    问题: 每次踢人都会重置邀请码，这在逻辑上不太合理，且可能被利用来反复重置其他群的邀请码。
    建议: 踢人操作不应重置邀请码。

19. 私聊消息撤回是硬删除
    文件: rpc/core.php 第3130行
    代码:
      csac_execute('DELETE FROM private_msg WHERE id = ?', 'i', $msgId);
    问题: 群聊撤回使用软删除（was_replied 标记），但私聊撤回直接 DELETE，不一致且无法审计。
    建议: 私聊也使用软删除标记，保持一致性。

20. friend_relation 表状态管理混乱
    问题: friend_relation.status 有多种值（0=待处理, 1=好友, 2=删除, 3=?, 4=拉黑），但删除和拉黑都通过同一个函数处理，状态语义不清晰。status=3 的含义在代码中未明确定义。
    建议: 使用常量定义状态值，并补充 status=3 的文档说明。


四、低风险/代码质量问题
----------------------------------------

21. index.html 描述和标题未定制
    文件: index.html 第9行
    问题: 仍使用 Flutter 默认描述 "A new Flutter project."，标题为 "csac"。
    建议: 更新为实际的应用描述和标题。

22. manifest.json 使用默认配色和描述
    文件: manifest.json 第6-8行
    问题: 使用 Flutter 默认蓝色和描述。
    建议: 更新为应用实际的品牌色和描述。

23. flutter_bootstrap.js 中 buildConfig 包含空构建项
    文件: flutter_bootstrap.js 第39行
    问题: builds 数组第二项是空对象 {}，这可能是构建配置错误。
    建议: 检查 Flutter 构建配置，移除空构建项。

24. 函数命名风格不一致
    问题: 代码中混用了 camelCase（createInviteCode, resetRoomCode, getOnlineStatus 等）和 snake_case（csac_fetch_one, csac_input_string 等）。
    建议: 统一使用一种命名风格（推荐 snake_case，符合 PHP PSR 规范）。

25. 全局变量使用
    文件: rpc/core.php 第50-52行
    问题: 使用全局变量 $conn、$CSAC_INPUT、$CSAC_TABLE_COLUMNS，虽然通过函数封装访问，但仍存在全局状态污染风险。
    建议: 考虑使用类封装或依赖注入。

26. csac_api_message_get_group_msg 中 N+1 查询问题
    文件: rpc/core.php 第2880-2890行
    问题: 在循环中对每条消息的 reply_to 执行单独查询，当消息量大时会导致 N+1 查询性能问题。
    建议: 先收集所有 reply_to ID，然后一次性批量查询。

27. csac_api_message_get_mentions 统计不准确
    文件: rpc/core.php 第3145-3148行
    问题: 统计的是所有历史消息中的 @和回复数量，而不是未读的。返回字段 unread_mentions/unread_replies 具有误导性。
    建议: 要么改为统计未读的，要么修改返回字段名称。

28. .htaccess 未保护 .log 文件和 rpc/ 目录
    文件: .htaccess
    问题: 只对 index.html、.php、.js、.css 设置了缓存头，但没有禁止访问 .log 文件、version.json 等可能泄露信息的文件。
    建议: 添加规则禁止访问 .log、.json（除 manifest.json 外）等敏感文件。

29. csac_ensure_schema 在每次请求时检查
    文件: rpc/core.php 第69-80行
    问题: Schema 迁移应通过独立的迁移脚本执行，而非在每次请求时检查。
    建议: 使用独立的数据库迁移工具。

30. 缺少速率限制
    问题: 登录、注册、发送消息等接口没有速率限制，容易被暴力破解或滥用。
    建议: 实现基于 IP 和 UID 的速率限制机制。
